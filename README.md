# umir-gateway

Единый API-вход. Маршруты `/api/serving/` и `/api/warehouse/` проксируются к соответствующим сервисам. Бизнес-решения выполняются внутри сервисов.

Это запускаемый каркас. Бизнес-логика кейса пока не реализована.

## Разработка

```sh
go test ./...
go vet ./...
go run ./cmd/server
```

`GET /healthz` сообщает о работоспособности процесса.

Сборка контейнера:

```sh
docker compose up --build -d
```

Согласованная система собирается в [umir-factory](https://github.com/JustIkra/umir-factory).

## Совместная работа

Владелец `main` — `JustIkra`: только он обновляет ветку и выполняет merge PR.
Приглашённые участники работают в других ветках. Остальные участники могут создать fork и PR.
Issue доступны всем пользователям GitHub.
Перед PR выполните локальные проверки. Код и настройки обсуждаются через PR.

## CI/CD

GitHub Actions проверяет ветки и PR. После успешной проверки `main` публикует образ
`ghcr.io/justikra/umir-gateway:sha-<полный SHA коммита>` для `linux/amd64` и `linux/arm64`.
Фабрика фиксирует выбранные SHA в своём `compose.yaml`. Публикация использует `GITHUB_TOKEN`.
Автоматический деплой на сервер не настроен.

Время приложения — `Europe/Moscow`. Секреты передаются через окружение; `.env` исключён из Git.
